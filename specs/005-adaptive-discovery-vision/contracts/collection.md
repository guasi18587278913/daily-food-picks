# 内部契约

- Provider.request 保留现有 pages 格式，增加 hot/inspiration/topic/faved；options 指定缓存或强制新发现，所有收费仍经过预算。
- normalizeNote 保留旧字段，增加仅后台使用的有界 media 与真实 topics；缺值保持未知。
- Discovery 生成持久化、有上限的任务，扩展真实线索和候选，不直接调用模型或发布。
- Reuse 校验版本、内容标识、有效期和采样时刻；写入需租约与单调时间。
- extractFrames 只接受经校验的视频定位信息，返回有顺序/采样时刻/摘要的 JPEG；不接受任意路径或任意网址。
- reviewVideo 必须发送真实图像，费用先预留；返回带帧号的可见证据，缺授权、密钥、预算或画面时零模型调用。
- runner 只给文字 uncertain 且数字条件适用的视频做复核；阶段开始要持久化，未知结果不重复收费。
- 客户端 API 无新增收费动作；coverage 仅用真实覆盖与缺口解释结果。

## 审查后明确的边界

- 发现上限18/4包括元数据、派生请求及重试；purpose写入dfp_attempts，与轮/日/补跑留额在同一事务预留。author/user按用途标注；固定发现端点不能伪装inspection。缓存与已完成同轮请求不重扣，每tick仍最多10个外部尝试。
- 热点、灵感和公开性资料仅是元数据成功；search/topic/author/faved才是作品发现。分别记录新请求、缓存、元数据和作品发现；元数据成功不能覆盖作品查询全部失败。每轮优先一次forceFresh作品查询。
- 初始候选保留本周→低粉→今日交错，40篇为整轮累计。附带作品只追加未处理尾部；恢复不重排。来源统计从持久化候选和请求归纳，按轮次提交一次；预算或服务未完成不算内容失败。
- 接近门槛定义为点赞落在300/1000/10000任一值的80%–120%，或粉丝4000–6000，有效期1小时；其余相关资料最多6小时。较新有效搜索指标优先，旧缓存仅补正文；标题/正文片段、发布时间或视频标识矛盾时重新取详情。
- 视觉改用直接VITA接口 `https://api.vita.cloud.tencent.com/v1/video2text/chat/completions`，模型 `vita-video-3.0`。该接口的 `max_tokens=16384` 表示输入输出合计上限，`max_completion_tokens=1024` 表示输出上限。按输入16384、输出1024保守预留23245微元人民币，不沿用TokenHub语义。
- 视觉金额使用整数微元人民币，日账上限500000、首验上限200000。首验最多6次并同时计日账，正式轮每轮最多3次；首验是独立验收范围，不伪造正式轮次。
- 视觉请求编号绑定范围/轮次、内容、帧摘要、规则与模型；reserved→inflight→received/failed/unknown。合法usage才按向上取整的实际token费用结算，缺usage、超时或未知保持预留。超出契约用量即停止通道并对账，不缩小费用凑上限。结算使用请求原日账并验证所有者。
- 直接VITA已实测支持Base64。当前V3待验实现以六个image_url发送独立JPEG，逐帧摘要与请求编号绑定，拒绝外部URL替换；不换收费模型，原始画面与缓存引用不进入客户端。

# Feature Specification: 多入口内容发现与视频画面复核

**Feature Branch**: `feature/adaptive-discovery-vision`
**Created**: 2026-09-14
**Status**: 需求已明确；实施及授权进展见 [tasks.md](tasks.md)
**Input**: 用户要求把实测过的六种找法接入现有流程、探索更省成本的抓取方式，并解决自动判断只读文字、不能看视频画面的问题。

## User Scenarios & Testing

### User Story 1 - 在固定费用内发现更多可核验作品（P1）

成员打开工作台时，看到来自多个线索入口、符合现有板块门槛的制作内容。运营者能知道每个入口花了多少、找到了多少、哪些没有查完。

**Independent Test**: 使用包含热点、主题、作者、话题、公开收藏和详情附带作品的记录回放，验证候选进入统一检查流程并按编号去重。

1. **Given** 热点只提供名称，**When** 继续查找，**Then** 用名称定位作品，不把热点编号或热度冒作作品编号与点赞。
2. **Given** 一次详情返回目标和其他作品，**When** 其他作品也符合时间与热度初筛，**Then** 它们进入有上限的候选队列，不因发现而立即入选。
3. **Given** 多个入口返回同一作品，**When** 处理该轮候选，**Then** 只做一次必要的细查与判断，并保留发现来源。
4. **Given** 公开收藏入口，**When** 未确认该作者允许公开收藏，**Then** 不尝试读取；公开后仍逐篇核验主题和时效。

### User Story 2 - 画面中的做法也能被自动识别（P1）

做菜步骤仅在视频里、文字不足的作品，可以经画面复核入选；只有成品、吃播、宠物或无关画面不能凭标题获得放行。

**Independent Test**: 对已知漏收的两段教程与非制作对照执行真正的视觉判断，保存采样时刻、可见证据、判断与费用。

1. **Given** 视频已达到板块数字门槛但文字证据不足，**When** 视觉调用已获授权且预算足够，**Then** 自动抽取多个有时间顺序的画面，再按可见制作操作或配方判断。
2. **Given** 只有成品近照或吃播画面，**When** 标题宣称“教程”，**Then** 视觉复核仍需画面依据，证据不足时不入选。
3. **Given** 视频下载失败、画面不可读、视觉服务失败或额度不足，**When** 收尾，**Then** 不冒充已看完、不放宽为做菜，并明确覆盖缺口。
4. **Given** 同一视频和相同判断规则已复核，**When** 在有效期内再次遇到，**Then** 复用判断，不再次收费看相同画面。

### User Story 3 - 避免重复与低效消费（P1）

保留已批准的采集时刻、板块门槛与请求上限，同时让低效搜索少占额度，为确认候选保留费用。

**Independent Test**: 对同一批候选进行重复处理，比较旧流程与复用流程的外部调用数；在并发、重启和失败条件下验证总费用与结果一致性。

1. **Given** 详情、粉丝或判断结果尚在明确有效期内，**When** 再次需要相同资料，**Then** 复用并保存真实采样时间，不能将缓存时间改成新采集时间。
2. **Given** 多个发现入口竞争额度，**When** 规划新轮次，**Then** 优先安排有有效候选记录的入口，也给其他入口保留探索机会；不把未检查候选当作无效样本。
3. **Given** 已有足够候选或达到发现阶段上限，**When** 还剩发现任务，**Then** 转入细查，不先把额度全部花在搜索上。
4. **Given** 重复执行或未知收费结果，**When** 恢复任务，**Then** 沿用请求记录，不清账、不猜测退款，不重新打开已关闭的实验额度。

### User Story 4 - 正常使用和运行问题可解释（P2）

沿用账号权限、查看、搜索、排序、收藏和往期功能；后台未完成时解释实际情况。

**Independent Test**: 确认读取入口没有新收费副作用，部分成功可发布，严重失败保留旧批次；来源、缓存和视频复核状态可在运行记录复查。

### Edge Cases

- 只有热点名称，没有真实话题标识；话题和收藏返回旧作品、推广或空结果。
- 同一作品由多个入口或详情附带列表返回；附带列表循环关联。
- 缓存过期、采样时刻在未来、规则或正文或视频内容变更；旧工作者晚到。
- 有效作品没有标题、没有视频地址、只有一帧、超长或损坏视频；视觉模型忽略图片或输出无依据。
- 跨轮、跨日、重复触发、租约失效、输入超长、模型错误、收费结果未知。
- 查找已停止但细查尚未完成；新入口全部失败；不能拿保留的旧结果冒充新发现。

## Requirements

### Functional Requirements

- **FR-001**: 接入热点、普通创作灵感、话题、作者近期作品、公开收藏和详情附带作品六种发现方式，并保留固定关键词探索。执行顺序与频率受预算和证据影响，不要求每轮把所有入口都调用一次。
- **FR-002**: 所有入口共用作品编号去重、数字初筛、内容核验和原有发布流程；新入口没有降低门槛的特权。
- **FR-003**: 保留 06/09/12/20 时刻、今日 24 小时千赞、本周 7 天万赞、黑马 5 天三百赞且粉丝不超过五千、历史七篇参照、跨轮已推荐去重及当天 06:00 沿用规则。本周仍不改为累计榜。
- **FR-004**: 新模式以轮换词表和多入口替代每天必扫全部 55 词。实际查过的入口、词和页数、因额度未查部分必须记录；旧模式可作为明确配置的回退方式，不承诺同等全站覆盖。
- **FR-005**: 发现阶段须有独立上限，为细查留下额度。保留每轮 40 个候选及文字判断上限；附带作品扩展不能无限递归或打乱已持久化的处理顺序。
- **FR-006**: 每轮至少有一次新的候选发现请求。缓存和历史数据只能用于减少重复取数，不能用仅改更新时间冒充新轮次采集。
- **FR-007**: 保存每个来源的请求数、去重后的数字候选数、实际检查数、通过数及失败；只用已检查结果评价质量。弱入口应降频或暂缓，保留明确的探索机会。
- **FR-008**: 复用详情、作者资料及内容判断时验证内容标识、采样时刻、有效期和规则版本；未知字段不补零、数据不足不编造倍数。
- **FR-009**: 新的视频复核仅作用于热度和时间可能入选、文字证据不足的视频。明确通过或有排除证据的内容不重复送视觉服务。
- **FR-010**: 视觉判断必须真实收到视频采样画面，输出对应画面序号及可见制作证据；只有成品展示或标题宣称不能作为画面制作证据。保存文字和视觉结果的区别，不称完整观看。
- **FR-011**: 文字判断保持原赠额通道。视觉模型为单独授权的费用项，缺授权、价格、密钥或额度时不发送；次数、输入输出和费用均有上限，失败不转投另一收费模型。
- **FR-012**: 按2026-09-14用户要求提高额度：显式expanded250配置下每日最多250次／2.50美元（含已有追加研究记账）、06:00最多100、常规与临时补跑每轮最多50；旧配置仍保留150次及17/17/16。临时补跑必须保留之后常规轮额度，不清账。
- **FR-013**: 视觉费用与数据请求分币种核算、调用前预留；失败或结果未知不释放可能已花的额度。已确认实际用量可按明确结算规则记录，不隐藏费用。
- **FR-014**: 读取、搜索、排序和收藏不能触发采集或视觉调用。密钥、原始视频和私有审计不进入客户端；临时视频与画面在使用后清理。
- **FR-015**: 发现、细查、文字判断、视频复核、缓存和发布各自可观察。未完成必要视频复核时不能将该作品计为通过，整体状态不能伪装完整成功。

### Key Entities

- 发现来源与任务：来源类型、真实参数、父线索、有效期、实际产出和检查进度。
- 候选与复用资料：作品标识、采样时间、来源集合、完整度及适用规则。
- 视觉核验：视频内容标识、采样时刻、画面数量、模型、证据和结果。
- 费用记录：数据请求与视觉调用的独立预留、实际或未知结果、每轮及每日上限。

## Success Criteria

- **SC-001**: 六种发现方式各有可重复验证的入池用例；重复作品只进入一个候选记录，且不会重复检查。
- **SC-002**: 已知两段漏收教程能在无人工改写判定的情况下经视觉核验通过；非制作和不可读对照不误收。实际测试数量与所有误差如实记录。
- **SC-003**: 同一批仍在有效期内的候选重复处理时，详情及判断重复调用至少减少 50%，符合条件的输出一致；不能靠丢弃候选制造省钱结果。
- **SC-004**: 并发、跨日、重启和未知结果的验证均不超已批准次数及金额，不侵占后续正常轮预留，不改变账号权限。
- **SC-005**: 用真实服务完成有界验证，费用、采样依据和判断可追溯；上线后真实轮次另行观察，不能将回放或助手看图替代生产验收。

## Assumptions

- 此功能修订 001 的固定发现方式、文字唯一证据及每轮全部重复获取假设，其余既有规则继续适用。
- 用户已授权接入与成本优化；用户另已明确允许视觉每轮最多3次、每日0.50元，首验最多6次/0.20元。仅本地开发不视为自动部署或无限付费许可。
- 评论需求、跨平台采集、累计榜和新增用户界面不属于本次范围。
- 原始试验数据仅作验证证据，不直接作为生产推荐结果导入。

## 2026-09-14即时补跑与额度修订

用户先要求现在测试，再明确“16次TikHub请求可以往上多调”。本轮说明并采用每常规轮50、每日250/$2.50、06:00保持100，当前补跑最多50并保留20:00的50；视觉3次/轮、0.50元/日不变。扩容通过明确服务器tier启用，常规发现最多8次、候选目标20、整轮候选40和文字20次不变。旧配置、已完成轮次和一次性研究账保持原样。

## 2026-09-14 视觉次数修订

用户明确要求“视觉提高到每轮最多20次”。后续新轮次视觉调用上限20，每日费用上限仍为0.50元，触及任一上限停止；已创建轮次保留原定义，旧实验账不重开。模型、图像输入、内容门槛、调用前预留和失败处理均不变。此设置是次数上限，不承诺每轮都能完成20个视频；采集窗口、文字判断及可用素材仍构成约束。

## 2026-09-15 候选不足修复

用户要求直接解决抓取内容偏少，完成后报告。新expanded250轮次不再用发现18/8次的固定终点：按已找到候选保留细查费用，在轮次与日费用范围内继续有效发现；所有原有时间、点赞、粉丝及制作证据门槛保留。旧已运行轮次继续原定义。候选不足且初始队列耗尽时允许追加未尝试固定词，保持图文/视频区分和既有任务总上限；06:00复用话题也按时间排序。

视觉输出无效与网络/服务失败必须分开记录，错误结论不当作不做菜。新增安全校验原因和调用编号；不保存原始输出，不添加自动付费重试。原判定规则和20次/轮、0.50元/日限制不变，明确模型输出证据结构后需真实补跑验证。

首轮真实补跑17篇候选仅1篇入选后，继续按用户要求修正：仅竞争黑马且粉丝未知时，免费复用仍有效的作者粉丝缓存进行预筛。首批候选核验结束后，如果还有文字/时间/候选容量与预算，可继续发现新候选；保留累计40、任务64、文字20及视觉20限制。已完成轮次不改回运行中，不重复推荐旧作品来填数量。

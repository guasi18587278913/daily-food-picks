# Research: 选题台界面视觉改版

**Feature**: [spec.md](spec.md) · **Plan**: [plan.md](plan.md) · **Date**: 2026-09-13

本文件记录方向 A 落到小程序时的具体取舍。数值以 375pt 宽屏幕换算（1pt = 2rpx）。

## R1. 颜色令牌

- **Decision**:

  | 令牌 | 值 | 用途 |
  | --- | --- | --- |
  | `bg` | `#F6F4F0` | 页面、标题栏、下拉刷新区 |
  | `card` | `#FFFFFF` | 卡片、搜索框、空板块行 |
  | `line` | `#ECE7E0` | 细边框、分段控件底 |
  | `placeholder` | `#F1ECE5` | 封面占位 |
  | `text` | `#1F1B18` | 标题、正文 |
  | `text2` | `#5C554F` | 对比说明、提示正文 |
  | `text3` | `#736B64` | 作者、时间、规则说明 |
  | `accent` | `#EA5A2B` | 26pt 主数字、已收藏星标、今日新锐色标 |
  | `accentInk` | `#B8441A` | 小号强调文字、主按钮和提示条底色 |
  | `accentSoft` | `#FDEEE7` | 选中胶囊、说明底色、已收藏按钮底 |
  | `week` / `dark` | `#C98A12` / `#3E8E68` | 本周热门、低粉黑马色标；部分更新、已更新状态点 |

- **Rationale**: 暖白和白卡片保留“食物”温度，但比现在的米黄纸本更干净；只保留一个橙色系，两个明度分别满足大字和小字的对比度。2026-09-13 用 WCAG 公式核对 14 组组合，全部通过：正文 17.10:1，`text3` 在页面底色上 4.76:1，`accentInk` 在白底 5.41:1，白字在 `accentInk` 上 5.41:1，`accent` 在白底 3.50:1（仅用于不小于 24pt 的数字）。
- **Alternatives considered**: 设计库 AI Calorie Tracker 原色 `#FE9B66` 在白底约 2.2:1，数字不达标，因此加深；白字放在 `accent` 上只有 3.50:1，小号按钮文字不达标，改用 `accentInk` 做按钮底。

## R2. 字号与字重

- **Decision**: 使用系统字体（iOS 苹方、安卓系统中文字体），不加载外部字体。

  | 元素 | 字号 | 字重 |
  | --- | --- | --- |
  | 作者、时间、规则、状态行、类型标签、对比说明 | 24rpx（12pt） | 400 |
  | 排序胶囊、提示正文、条数 | 26rpx（13pt） | 400／600 |
  | 按钮文字 | 28rpx（14pt） | 600 |
  | 卡片标题、搜索、分段切换 | 30rpx（15pt） | 600／400 |
  | 板块名称 | 34rpx（17pt） | 700 |
  | 轮次标题 | 40rpx（20pt） | 700 |
  | 主数字 | 52rpx（26pt） | 700，等宽数字 |

- **Rationale**: 满足 FR-003；层级靠字号和字重拉开，不再混用衬线体。
- **Alternatives considered**: 引入 Inter 等西文字体：中文仍回落系统字体，且需要联网下载，违反 FR-013。

## R3. 卡片版式

- **Decision**: 卡片内边距 24rpx，圆角 32rpx，浅阴影。左侧封面 216×288rpx（3:4），圆角 24rpx，裁切填充，左下角标“视频／图文”。右侧：标题最多两行、作者与日期单行省略、主数字贴底、对比说明一行。底部为分隔线和操作行：左侧收藏胶囊（已收藏为浅橙底 + 实心星），右侧“复制原文”文字按钮；两者点击高度 88rpx。
- **Rationale**: 用户选定左图右文。封面面积约为现在的 2.3 倍，一屏约 2 条，数字与说明完整。
- **Alternatives considered**: 上图下文、双列网格已由用户在澄清中放弃。

## R4. 顶部与板块结构

- **Decision**: 使用原生标题栏，不做自定义导航。页面顶部依次为状态行（状态点 + 状态 + 每日更新时刻）、分段切换（选题台／我的收藏 + 数量）与“往期”按钮、搜索框。轮次标题下显示整理时间和部分更新说明。板块顺序固定为今日新锐、本周热门、低粉黑马；有内容时显示名称、条数、规则、排序胶囊和卡片，为 0 时显示 96rpx 高的一行（色标、名称、规则省略、“本轮暂无”）。
- **Rationale**: 移除重复品牌区可节省约 90pt；空板块从约 110pt 降到 48pt。固定顺序比“有内容的板块排前面”更容易预期。
- **Alternatives considered**: 自定义导航栏需要处理状态栏高度和胶囊按钮，收益小；动态调整板块顺序会让用户找不到固定位置。

## R5. 图标

- **Decision**: 在 `app.wxss` 用内联 SVG 数据定义约 12 个线性图标类（搜索、清空、往期、展开、收藏空心／实心、复制、提示、锁、刷新、箭头、空状态）。需要不同颜色时各定义一份。
- **Rationale**: 不新增图片文件，避免文件数超过标准任务上限；显示比文字符号稳定。
- **Alternatives considered**: 本地 SVG／PNG 文件会增加约 12 个文件；图标字体需要额外资源且安卓渲染不稳定；继续用文字符号不满足 FR-008。实施后在模拟器和真机核对安卓 SVG 背景显示，异常时改用内联 PNG 数据。

## R6. 点击区域

- **Decision**: 按钮外框至少 88rpx 高，视觉胶囊可以更小（排序胶囊视觉 60rpx，外框 88rpx）；相邻可点元素之间至少 16rpx。
- **Rationale**: 满足 FR-004，同时保持版面紧凑。
- **Alternatives considered**: 把视觉胶囊直接做到 88rpx 会显得笨重，挤占首屏。

## R7. 深色模式与宽屏

- **Decision**: 不开启小程序深色模式适配，页面固定浅色；内容最大宽度 750rpx 居中。
- **Rationale**: 满足 FR-012；深色模式不在本次范围。当前 `app.json` 未开启深色适配，保持即可。

## R8. 视觉验证方式

- **Decision**: 用开发依赖 `miniprogram-automator` 连接模拟器，按 [UI 状态契约](contracts/ui-states.md) 设置页面数据并截图；截图只保存在本机私有目录，不提交 Git。
- **Rationale**: 不需要在正式包里加入调试页面，也不写云端数据。
- **Alternatives considered**: 调试专用页面会进入正式包；等待真实云端出现每种状态不可控。

## R9. 设计参考的使用边界

- **Decision**: 只参考设计库 AI Calorie Tracker、Gear Shop、Bite-Sized Courses 的视觉语言（食物图卡片、大号数字、胶囊筛选、奶白底），不复制其提示词、网页代码或示例文案。
- **Rationale**: 设计库条目为未验证的私有参考，网页实现不能直接用于小程序。

## R10. 微信按钮默认样式（实施中发现）

- **Decision**: 在 `app.wxss` 用 `button:not([size=mini]){width:auto;margin-left:0;margin-right:0}` 复位按钮宽度和外边距。
- **Rationale**: 2026-09-13 模拟器截图发现，`style: v2` 下按钮默认宽 184px、左右外边距自动，普通 `button{}` 复位的优先级不够，导致排序胶囊竖排、“往期”被挤出屏幕、搜索框文字被压没、新一轮提示条变窄。浏览器效果图没有这条默认样式，所以效果图阶段看不出来。
- **Alternatives considered**: 给每个按钮类单独写宽度，重复且容易漏；改用 `view` 模拟按钮，会失去按钮语义和点击态。

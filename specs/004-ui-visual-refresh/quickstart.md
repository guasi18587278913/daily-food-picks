# Quickstart: 验证选题台界面改版

**Feature**: [spec.md](spec.md) · **Plan**: [plan.md](plan.md) · **States**: [contracts/ui-states.md](contracts/ui-states.md)

本指南只描述验证步骤，不包含实现代码。所有命令在工作树根目录 `美食博主工作台-004-ui-refresh` 运行。

## 1. 前提

- 效果图已经用户确认（FR-014），确认时间写入 tasks。
- 工作树有可用依赖：优先 `npm ci`；离线时可临时链接主工作区的 `node_modules`，完成后删除链接，不提交。
- 已安装微信开发者工具并开启服务端口；开发者工具登录的是已授权的维护账号。
- 开发者工具升级后会换用新的配置目录：需要重新扫码登录，并在“设置 → 安全设置”重新打开“服务端口”，其余三个开关保持关闭。
- 状态截图脚本在本机 `.local/004-ui-shots/sim-check.js`（不提交）；运行后截图和 `report.json` 也保存在该目录。

## 2. 行为与类型

```bash
node --test tests/frontend.test.js
npm run typecheck:mini
```

预期：现有 11 项及新增展示用例全部通过，类型检查 0 错误。任何失败先判断是实现、测试还是环境问题，不能改断言凑通过。

## 3. 状态截图（模拟器）

1. 用 `miniprogram-automator` 打开本工作树项目，进入首页。
2. 按 [UI 状态契约](contracts/ui-states.md) 的 S01–S18，逐项设置页面数据后截图；卡片数据使用 9 月 12 日两轮真实选题，覆盖长标题、缺封面、未知指标。
3. 在 320、375、430pt 三种宽度各截首页一次，检查横向溢出和截断。
4. 截图保存到本机私有目录（如 `.local/004-ui-shots/`），不提交 Git。

预期：与确认后的效果图一致；375×667pt 首屏可见第一张卡片的封面和标题首行；无旧颜色、衬线混排或文字符号图标。

注意：打开页面会调用只读接口，不触发收费采集。若开发者工具账号不在名单中，只记录未开通状态，不反复打开。

## 4. 样式核对

逐项核对 FR-003、FR-004：

- 可见文字不小于 24rpx，卡片标题不小于 30rpx，主数字不小于 48rpx。
- 可点击元素外框高度不小于 88rpx。
- 颜色只使用 [research.md](research.md) R1 的令牌。

## 5. 真实数据回归

在模拟器重新进入首页，等待真实最新轮次加载，依次执行：进入、查看更新、搜索、排序、收藏后重开、复制来源。记录环境为“模拟器”。

```bash
npm run check:package
```

预期：通过，没有私有文件或截图进入小程序包。

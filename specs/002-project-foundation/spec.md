# Feature Specification: 统一目录与双工具 SDD 开发地基

**Feature Branch**: 沿用现有本地分支；规格目录与 Git 分支名独立。
**Created**: 2026-09-13
**Status**: 已实现并完成本地验证及独立审查。详见[任务清单](tasks.md)与[整理记录](../../docs/operations/project-organization.md)。
**Input**: 将开发规范结合 Codex、Claude Code 和既有 Spec Kit，解决规格与源码分处两目录的问题，并整理零散资料。

## User Scenarios & Testing

### User Story 1 - 从一个项目目录开发 (Priority: P1)

维护者打开同一个项目，就能找到源码、当前功能规格和开发规则。

**Why this priority**: 目录分离会让开发工具丢失需求或修改错误位置。
**Independent Test**: 从新主目录与原源码入口定位项目和当前功能，结果指向同一份材料。

**Acceptance Scenarios**:

1. **Given** 已有源码与完整历史，**When** 整理完成，**Then** 原提交、分支、远端配置和业务源码内容保留。
2. **Given** 旧工具仍引用原源码目录，**When** 访问该入口，**Then** 进入同一主项目，不出现第二份独立代码。
3. **Given** 微信指定成员试用仍有待办，**When** 恢复该功能，**Then** 原需求、任务和剩余验收仍能找到。

### User Story 2 - 两种工具共同执行规范 (Priority: P1)

Codex 和 Claude Code 使用同一套原则与功能材料，能按已有进度继续开发和交接。

**Why this priority**: 工具切换不能造成规则分叉或重复开发。
**Independent Test**: 从两种入口找到相同原则、功能和验证方式，并用新功能、继续任务、只读咨询三个场景检查流程选择。

**Acceptance Scenarios**:

1. **Given** 长期原则原为模板，**When** 整合完成，**Then** 原则明确并与细则相连，没有未填项。
2. **Given** 使用任一工具，**When** 接手任务，**Then** 读取相同规则和任务状态，工具调用差异不复制业务规则。
3. **Given** 任务已获授权，**When** 换工具继续，**Then** 不重新访谈或重新生成已有方案。
4. **Given** 用户只要讨论，**When** 使用开发入口，**Then** 不自动实现、部署或调用收费服务。

### User Story 3 - 按用途找到资料 (Priority: P2)

维护者能区分当前规范、功能规格、运行记录、历史研究、原始响应、品牌素材和本地临时产物。

**Why this priority**: 避免旧结论当作当前事实，也让根目录可浏览。
**Independent Test**: 从首页定位各类材料，检查整理前文件的去向和完整性。

**Acceptance Scenarios**:

1. **Given** 零散文档，**When** 归档完成，**Then** 每份有明确位置，重要链接可访问。
2. **Given** 原始数据和私有配置，**When** 加入版本管理，**Then** 保持本地隔离，不混入默认待提交文件。
3. **Given** 需要核查迁移，**When** 查看迁移记录，**Then** 能找到备份、去向及有意修订说明。

### Edge Cases

- 同名文件、未提交改动、活动工作树或迁移途中变化，不能静默覆盖。
- 旧路径、相对链接、生成副本和私有文件的忽略规则失效。
- 两种工具同时修改功能选择或任务状态。
- 归档脚本含收费能力，整理不能触发历史采集。

## Requirements

### Functional Requirements

- **FR-001**: 必须有一个明确主入口，源码与规格共同保存。
- **FR-002**: 保留原历史、业务内容和可恢复记录，不删除原始资料。
- **FR-003**: 旧源码路径到达同一项目，不长期保留两份独立代码。
- **FR-004**: 两种工具共享长期原则、专题规范和单次功能材料。
- **FR-005**: 沿用既有规格驱动流程与授权，明确接续和交接。
- **FR-006**: 资料按用途组织，首页导航当前工作与历史参考。
- **FR-007**: 私有配置、原始响应、二维码和临时日志保持本地隔离。
- **FR-008**: 实际验证完整性、链接、功能定位与共享入口，并独立审查。

### Key Entities

- 项目入口：唯一主位置与兼容入口。
- 功能：需求、方案、任务及对应证据。
- 资料：当前规则、运行事实或历史材料。
- 迁移记录：原位置、新位置、完整性依据与有意修订。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 新旧入口定位到同一项目和同一当前功能。
- **SC-002**: 整理前每个记录文件均有去向，无未解释丢失或内容变化。
- **SC-003**: 两种入口找到同一规范，三个流程场景判断一致。
- **SC-004**: 当前开发文档本地链接可解析，私有材料不会默认加入版本控制。
- **SC-005**: 业务源码内容一致，整理不产生云端写入或收费调用。

## Assumptions

- 保留用户当前打开的项目目录为主入口。
- 沿用现有本地分支，不推送、合并或部署。
- 旧网页运行文件保留相对结构，历史试跑按原样归档。
- 本次不安装新的检查框架或 CI，不改采集和权限业务逻辑。

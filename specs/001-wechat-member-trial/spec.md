# Feature Specification: 定时更新的微信指定成员试用版

**Feature ID**: `001-wechat-member-trial`

**Feature Branch**: `feature/wechat-member-trial`；功能目录与分支名独立。

**Created**: 2026-09-12

**Status**: 实施进度以[任务清单](tasks.md)为准，实际部署与指定成员验收见[运行记录](../../docs/operations/wechat-trial-runbook.md)。本文件维护需求和验收约定。

**Input**: 用户要求用 Spec Kit 落地；首轮让大芙等指定成员在微信里试用；试用版今天必须能定时更新新数据；没有现成服务器，按腾讯云方案准备；实际只有大芙一人使用，要求尽量降低成本，并核实个人开发者政策。

## User Scenarios & Testing

### User Story 1 - 无人值守产生新选题 (Priority: P1)

到达预定时刻后，即使开发者电脑关闭，也会重新采集、筛选并保存本轮选题。运营者不用手动运行脚本、判断每篇内容、编辑数据文件或重新上传小程序。

**Why this priority**: 用户已明确，静态样本只能用于开发，不能作为本次交付。

**Independent Test**: 在腾讯云配置一个即将到达的验收触发时刻，关闭本地采集进程，等真实定时器触发并完成采集；记录新请求、窗口、筛选依据和结果，确认无需人工补写判断。

**Acceptance Scenarios**:

1. **Given** 到达北京时间 09:00、12:00 或 20:00，**When** 平台触发该轮任务，**Then** 使用对应窗口重新获取数据，记录计划时刻、实际采集时间和完成时间。
2. **Given** 内容采集成功，**When** 判断候选是否为制作类内容，**Then** 必须找到做法、配方或制作过程的证据；仅标题出现美食词、仅探店或吃播不能入选。
3. **Given** 原文证据不足或判断失败，**When** 计算结果，**Then** 记录待核验或失败，不编造内容，不把人工补判断作为每轮必经步骤。
4. **Given** 同一轮被重复触发、运行中断后恢复，**When** 继续执行，**Then** 不重复创建轮次、发布推荐或无条件重跑已完成请求。
5. **Given** 达到已批准的请求或费用上限，**When** 准备下一次收费调用，**Then** 停止新增消费，保留进度并记录覆盖范围；不得自动充值或增加额度。
6. **Given** 本轮成功但零入选、部分覆盖或整体失败，**When** 生成状态，**Then** 三种情况能区分；失败不能伪装成“暂无新爆款”。

### User Story 2 - 指定成员在微信看到更新 (Priority: P1)

大芙扫码打开微信体验版，查看今日爆款、本周大爆款、低粉黑马三个板块。新一轮完成后，打开或返回页面即可看到更新，无须重新安装或上传体验版。

**Why this priority**: 这是用户指定的实际交付方式。

**Independent Test**: 一名已授权成员和一名未授权账号分别扫描体验码；已授权成员打开后等待云端新一轮发布，验证内容及时间更新，未授权账号不能看到试用数据。

**Acceptance Scenarios**:

1. **Given** 大芙已获得体验资格，**When** 扫描体验码，**Then** 能进入选题页，看到三个板块、轮次日期和真实完成时间。
2. **Given** 新一轮仍在运行，**When** 打开页面，**Then** 保留最近成功结果，明确标注其日期，并显示更新中。
3. **Given** 新一轮已成功发布，**When** 重新打开、返回页面或前台自动检查，**Then** 60 秒内显示新结果；新结果不依赖上传新的小程序版本。
4. **Given** 当前轮次失败，**When** 查看页面，**Then** 保留上一轮结果并显示更新失败；无历史结果则显示尚无可用结果。
5. **Given** 某板块为空或封面缺失，**When** 阅读列表，**Then** 展示合理空状态或封面占位，不妨碍其余内容。
6. **Given** 未授权账号，**When** 尝试进入或直接读取试用数据，**Then** 拒绝访问，不返回选题、图片地址或采集日志。

### User Story 3 - 搜索、排序与回看 (Priority: P2)

试用者按标题、作者或正文关键词搜索，在板块内按已有指标排序，按轮次回看历史。

**Why this priority**: 延续网页的核心筛选能力；仍属于本次完整交付范围。

**Independent Test**: 用两轮确定数据验证查询、无结果、清空搜索、排序和轮次切换；测试数据只能存在于测试环境。

**Acceptance Scenarios**:

1. **Given** 笔记标题、作者或正文包含关键词，**When** 搜索，**Then** 在已保存的试用轮次中找到对应作品；同一笔记在搜索结果中只显示一次。
2. **Given** 没有结果，**When** 搜索，**Then** 显示无结果；清空后恢复当前轮次列表。
3. **Given** 切换点赞、收藏、评论或适用的倍数排序，**When** 查看板块，**Then** 顺序与指标一致；未知值显示暂无，不填零。
4. **Given** 选择往期，**When** 切换，**Then** 日期、板块和指标来自同一轮；新一轮发布不会把正在阅读的往期强制切走。

### User Story 4 - 收藏并找到原文 (Priority: P2)

试用者收藏感兴趣的笔记，稍后回看；通过复制来源链接，在小红书里找到原文。

**Why this priority**: 完成从发现选题到实际研究内容的使用闭环；仍属于本次完整交付范围。

**Independent Test**: 收藏、取消、关闭后重开；复制至少两篇真实作品链接并核对目标，验证保存和复制失败时不会显示成功。

**Acceptance Scenarios**:

1. **Given** 点击收藏或取消，**When** 保存成功，**Then** 列表和状态同步；相同设备、相同微信账号重开后结果仍在。
2. **Given** 存储失败，**When** 收藏，**Then** 明确提示失败，不显示虚假的成功状态。
3. **Given** 已收藏作品跨出最新轮次，**When** 查看收藏，**Then** 仍能从往期找到；目标已不可用则提示并允许取消。
4. **Given** 主动点击复制来源链接，**When** 复制成功，**Then** 提示自行到小红书打开；失败时不提示成功。
5. **Given** 普通扫码进入小程序，**When** 查看原文入口，**Then** 不承诺无法实现的一键打开任意外部应用。

### Edge Cases

- 重复定时事件、函数超时、重试、任务租约过期、跨日预算、两轮任务重叠。
- 外部请求已发出但结果未知：费用占用不能凭猜测退回；重试需要新额度。
- 时间窗口边界、置顶状态未知、作者历史不足、点赞缺失或中位数为零。
- 搜索分页被截断、供应商数据过旧、原文截断、分类不确定、封面下载失败。
- 缺少任何预算、供应商报价发生变化、密钥失效时停止相应收费流程。
- 最近成功快照与当前失败任务并存；历史轮次、最新轮次和个人收藏互不串改。
- 小程序账号没有上传权限、未添加成员、账号状态不支持当前体验操作。

## Requirements

### Functional Requirements

- **FR-001**: 首轮交付微信体验版给管理员指定成员，不以公众可搜索或正式上架为目标。
- **FR-002**: 按北京时间每天 09:00、12:00、20:00 建立独立采集轮次；开发者电脑离线不影响运行。这里先将三个时刻定义为触发时刻，不能承诺整点已经采集完毕。
- **FR-003**: 每轮真实重新获取候选及需要的指标；旧样本、重复上传旧数据或仅修改更新时间均不算定时更新。
- **FR-004**: 每轮无需人工逐篇补写内容判断；依据可读取正文识别做法、配方或制作过程，保存判断及证据，不确定则暂不推荐。
- **FR-005**: 保留当前三个板块的已展示门槛：今日爆款过去 24 小时且点赞至少 1000；本周大爆款过去 7 天且点赞至少 10000；低粉黑马点赞至少 300、作者粉丝至多 5000。所有板块均须符合制作内容条件。
- **FR-006**: 用户于 2026-09-12 明确：倍数按作者此前 7 篇作品点赞中位数计算，低粉黑马查看近 5 天。该选择替代旧需求的 5 篇及后加脚本的 24 小时黑马窗口；粉丝上限仍为 5000。
- **FR-007**: 倍数根据候选发布前的作者历史确定，不包含候选自身或之后作品；排除明确置顶视频，置顶状态未知不能当作未置顶；历史不足、缺值或中位数为零不能编造倍数。今日板块采用现有页面绝对门槛，倍数用于排序，不额外恢复旧稿的五倍入选门槛。
- **FR-008**: 保留此前确认的跨轮次已推荐去重；同一作品成功推荐后不进入后续轮次的新推荐，仍保留在往期及收藏。三板块内部按作品编号去重，不人为凑固定条数。
- **FR-009**: 页面只读已保存结果，打开、刷新、搜索或收藏均不得触发收费采集。
- **FR-010**: 保存轮次计划时刻、实际采集起止、来源时间依据、候选及入选数量、覆盖范围、失败原因。未知来源刷新时间如实标记，不冒充实时全量覆盖。
- **FR-011**: 只有作品字段和入选依据通过校验后，才能发布可用结果；覆盖有限但有有效作品时允许发布明确标记的部分结果。运行中或整体失败时保留旧结果并显示真实日期。
- **FR-012**: 对成功零结果、完成但覆盖有限、更新中、超额暂停和失败设置不同状态；有未完成必要步骤时不发布为完整成功。
- **FR-013**: 对首轮验证、单轮和每日设置明确费用及请求次数上限，包含数据接口、内容判断和重试；缺少批准值时不发起收费调用。云资源费用另列。
- **FR-014**: 重复触发、任务恢复和发布都需防重；不能承诺对第三方已发出的计费请求绝对只收费一次，需记录不确定状态。
- **FR-015**: 保留搜索、去重、适用指标排序、往期查看和本机收藏；不承诺跨设备收藏或自动导入网页收藏。
- **FR-016**: 提供用户主动触发的原文复制与查看说明；复制失败、缺链接或外部内容不可访问不能伪装成功。
- **FR-017**: 小程序只取得展示数据；供应商密钥、腾讯云凭据、原始采集记录及管理能力仅在服务端使用，不打包或返回给客户端。
- **FR-018**: 云端读取必须核验平台可信身份和试用资格；不能相信客户端自报的成员身份。数据库和私有图片不允许客户端任意读取、写入或签发链接。
- **FR-019**: 试用者不需要提供手机号、头像、昵称或小红书登录凭据；成员授权仅服务于指定试用。
- **FR-020**: 前台每 60 秒检查一次更新，回到页面立即检查，后台停止轮询；停留在往期时只提示有新数据，不强制跳转。
- **FR-021**: 使用腾讯云承载定时任务及结果存储；先形成可复核的资源、权限、费用与验证方案，再按已确认方案开通部署。
- **FR-022**: 当日交付需要真实定时触发、真实新数据处理和指定成员真机使用的完整证据；手动执行或模拟器成功不能替代。
- **FR-023**: 按单个实际使用者设计，管理员仅为验收和维护保留访问；不建设自助注册、多客户管理、付费订阅或复杂后台。优先申请适用免费资源，再评估最低可用套餐。
- **FR-024**: 低成本不能悄悄改掉每日三个轮次、7 篇参照、5 天黑马和制作内容要求；减少搜索词或页数须明示覆盖取舍并经整体方案确认。

### Key Entities

- **采集轮次**：计划时刻、窗口、真实运行时间、状态、进度、规则版本、预算占用和结果引用。
- **采集请求**：所属轮次、请求用途、尝试次数、费用预留、结果状态与恢复依据。
- **候选作品**：来源编号、标题、作者、正文、发布时间、类型、互动数、粉丝数和来源链接。
- **判断依据**：是否制作内容、正文证据、历史参照作品、排除原因及所用规则版本。
- **发布快照**：完成校验的不可变轮次内容，供首页、往期及收藏读取。
- **试用成员**：微信平台识别的用户与服务端批准状态。
- **个人收藏**：当前用户使用环境内的笔记编号及收藏时间。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 今天至少完成一轮由腾讯云真实定时器触发的新数据采集、判断、保存、发布；本地采集进程关闭，过程中不人工补写判断。保留新请求及筛选证据，不以历史 34 篇冒充。
- **SC-002**: 正常时刻未赶上验收时，可配置一次即将发生的真实验收时刻，仍走同一链路和预算；验收后删除临时触发配置，保留每日三个正式时刻。
- **SC-003**: 至少一名指定成员真机完成进入、查看更新、搜索、排序、收藏重开、复制来源六项操作，六项全部通过；云端发布后 60 秒内可见更新。
- **SC-004**: 至少一个未授权身份读取被拒绝；不返回数据或图片访问地址。
- **SC-005**: 离线验证重复触发不重复发布、额度不足不发送请求、未知计费不退额度、中断能从已记录进度恢复；每项均有结果。
- **SC-006**: 本轮入选数据的时间窗口、编号去重和适用数值门槛全部通过自动校验；内容判断至少抽核 10 篇，有不足则核对全部，记录误收与漏收并处理阻塞项。
- **SC-007**: 所有验证证据绑定同一提交或工作区状态，记录退出码、通过数、失败数及未验证项。不能把当日一次通过描述成长期稳定；后续连续两个正式轮次另行观察。

## Assumptions

- 用户已明确实际使用者为大芙一人；首日必须定时产生新数据、无现成服务器、采用腾讯云并尽量降低成本。
- 每日三个触发时刻沿用旧需求已确认的 09:00、12:00、20:00；实际完成时间由本次真实采集测量，不承诺整点出结果。
- 用户已解决历史口径差异：作者参照为 7 篇，黑马窗口为 5 天；旧脚本不能不加修改地直接循环运行。
- 原有跨轮去重继续生效；如果用户希望“本周大爆款”持续保留旧榜单而非仅展示新入选，需先修改本条和 FR-008。
- 首版自动内容判断以正文证据为依据，证据不足暂不推荐；不追加视频下载、转录等收费链路。这可能漏掉只有视频含步骤的作品，需要在试跑报告体现。
- 首版只做本机收藏。大芙和维护者使用同一选题结果，不创建多客户独立选题库。
- 后续已完成个人账号注册、基本资料和成长计划资源领取；服务类目等待管理员扫码。备案、认证、体验权限、云套餐有效期/模型余额和首轮/日预算仍需分别核对，详见 enrollment-status.md。
- 数据接口、内容判断和云资源都可能计费；“按腾讯云方案准备”不等于已批准任意规格和无限费用。
- 当前 2026-09-10 的 34 篇仅可作为开发对照，不满足新数据交付验收。

## Scope Boundaries

本轮包含定时调度、自动采集与正文判断、预算控制、结果保存与读取、指定成员访问、原有页面能力迁移和真实微信体验交付。

本轮不包含正式公开发布、收费会员、跨设备收藏、完整视频下载/转录、用户评论发布、第三方账号代登录或向他人自动发送消息。

这是超过两个模块、预计超过十个文件，且涉及云部署、密钥与持续付费的高风险任务。按用户给出的 AGENTS.md，先完成调查和具体方案，待整体确认后实施；实施后安排独立审查并验证修复。

- 2026-09-12 实测校准：恢复原 dark_horse.py 已有的 300 赞门槛。原规格遗漏该项，不是新增产品门槛；补入 FR-005。

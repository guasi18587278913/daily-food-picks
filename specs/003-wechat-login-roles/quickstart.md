# 验证指南：微信登录与多用户权限体系

本文件只描述怎么验证，不含实现代码。实施步骤和完成状态见 [tasks.md](tasks.md)，真实部署与验收事实写入运行记录。

## 前置条件

- Node.js ≥ 20.19，仓库根目录已 `npm install`。
- 改动过云函数共享源或配置后，先 `npm run prepare:functions` 刷新生成副本。不要直接改副本。
- 云端验证需要已部署 `account` 函数、5 个新集合设为 ADMINONLY、`DFP_BOOTSTRAP_ADMIN_OPENID` 已配置。

## 本地验证（无需云端、无费用）

```bash
npm run prepare:functions     # 刷新生成副本
npm test                      # node --test tests/*.test.js
npm run typecheck:mini        # 小程序类型检查
npm run check:package         # 客户端包结构与副本一致性
```

开发中只跑受影响的文件，例如只改了邀请码逻辑：

```bash
node --test tests/invites.test.js
```

完成声明必须带实际结果：退出码、通过数、失败数、跳过数，以及对应的源码状态。

## 行为验证清单

下面每项对应 spec 的验收场景，全部用 `tests/helpers.js` 的 `MemoryStore` 在本地可验，不需要云端。

### 权限判定（spec FR-001～FR-006）

| 验证点 | 期望 |
| --- | --- |
| 身份缺失、AppID 不符、别名冲突 | `UNAUTHENTICATED`，不读取任何业务数据 |
| 请求参数里塞 `OPENID`／`APPID` | 被忽略，仍按调用上下文判定 |
| 用户记录不存在 | `NOT_REGISTERED`，响应不含选题作品、图片地址、轮次信息 |
| 用户记录 `status` 为 `suspended` | `SUSPENDED`，同样不含任何数据 |
| `role` 或 `status` 字段缺失、是非法值 | 按无权限处理，不放宽 |
| member 调用管理动作 | `FORBIDDEN`，不返回用户列表或码明文 |
| 同一次调用内多次需要权限 | 用户记录只读一次 |

`catalog` 的 5 个 action 和 `account` 的每个 action 都要逐个覆盖，不能只测入口。

### 邀请码核销（spec FR-008～FR-015）

| 验证点 | 期望 |
| --- | --- |
| 有效码、未用尽、未过期 | 开通为 `active`/`member`，记录 `grantedVia='invite'` 与码值 |
| 码不存在 / 已停用 | 都返回 `CODE_NOT_FOUND`，同一提示，不泄露是否曾存在 |
| 码已过期 | `CODE_EXPIRED` |
| 码已用尽 | `CODE_EXHAUSTED` |
| 同一身份重复提交同一有效码 | `ALREADY_REGISTERED`，`usedCount` 不变，不产生第二条记录 |
| **两个身份并发提交仅剩一次的码** | 只有一个成功，另一个 `CODE_EXHAUSTED`，`usedCount === maxUses`，不为负 |
| 已停用身份提交有效码 | `SUSPENDED`，不扣减次数 |
| 连续 10 次错误提交后再提交 | `TOO_MANY_ATTEMPTS`，带恢复时间，不读取邀请码文档 |
| 成功开通后 | 失败计数文档被删除 |
| 码值含小写、首尾空白、分隔符 | 归一化后正常核销 |
| 码值格式非法（长度、字符集） | `INVALID_ARGUMENT`，不查库 |
| 生成的码 | 符合 10 位指定字符集；连续生成多个不重复 |

并发用例借 `MemoryStore.transaction` 的串行化语义：同时发起两个 `redeem`，`await Promise.all`，断言结果与最终 `usedCount`。

### 管理动作（spec FR-016～FR-020）

| 验证点 | 期望 |
| --- | --- |
| admin 查看用户列表 | 分页正常；不含手机号、昵称、头像、他人收藏 |
| admin 停用 member | 该身份随后所有读取返回 `SUSPENDED`；其收藏文档仍存在 |
| admin 恢复该 member | 读取恢复正常；收藏内容与停用前一致 |
| **停用唯一的 active admin** | `LAST_ADMIN`，拒绝，状态不变 |
| **把唯一的 admin 降为 member** | `LAST_ADMIN`，拒绝，角色不变 |
| 有两个 admin 时停用其中一个 | 允许 |
| admin 停用邀请码 | 后续核销失败；已用该码开通的用户仍为 `active` |
| 每个成功的管理动作 | 写入一条 `dfp_access_log`，含操作者、类型、对象、时间 |

### 收藏（spec FR-021～FR-025）

| 验证点 | 期望 |
| --- | --- |
| 收藏、取消收藏 | 服务端状态同步，返回真实计数 |
| 换身份读取 | 只看到自己的，看不到他人的 |
| 请求参数传他人 openId | 无效，仍读写调用者自己的文档 |
| 本机有收藏、云端为空 | 合并后云端包含全部条目，`mergedAt` 非空 |
| 本机与云端都有不同条目 | 取并集；同一 noteId 保留较早时间戳 |
| 重复调用合并 | 幂等，不丢条目、不重复 |
| 合并写入失败 | 返回失败；本机副本保留，不清空 |
| 超过条数上限时新增 | `LIMIT_EXCEEDED`，不部分写入 |
| 被停用用户读写收藏 | `SUSPENDED`；恢复后数据完整 |

### 迁移（spec FR-026、FR-027）

| 验证点 | 期望 |
| --- | --- |
| 静态名单有 N 个身份、用户记录为空 | 建出 N 条 `active`/`member`，`grantedVia='migration'` |
| 重复执行迁移 | `created` 为 0，`skipped` 为 N，不产生重复记录 |
| 名单中某身份已被手动改为 admin | 迁移跳过，不覆盖角色 |
| 名单中某身份已被停用 | 迁移跳过，不把它改回 active |
| 迁移窗口内：用户记录不存在但在静态名单中 | 回落判定通过（仅窗口内版本） |
| 去掉回落后：用户记录不存在 | `NOT_REGISTERED`，即使仍在静态名单中 |
| 非 admin 调用迁移动作 | `FORBIDDEN` |

### 读次数优化（research.md 7.5 第 1、2 项）

| 验证点 | 期望 |
| --- | --- |
| 一次 `status` 调用 | 对 `dfp_snapshots` 的读取不超过 1 次（原为 2 次） |
| 一次 `getNotes` 取 N 篇、来自 M 个轮次 | 对 `dfp_snapshots` 的读取不超过 M 次（原为 N 次） |
| 优化后的返回值 | 与优化前逐字段相同，无行为变化 |

用计数型替身统计 `store.get` 的调用次数来断言，不靠人工数代码。

### 客户端界面分支（contracts/account-api.md「客户端约定」）

| 验证点 | 期望 |
| --- | --- |
| `me` 返回 `NOT_REGISTERED` | 只显示开通引导；**不发起任何选题数据请求**，不启动轮询 |
| `me` 返回 `SUSPENDED` | 显示停用提示；不发起选题请求，不轮询 |
| `me` 返回 `active`/`member` | 进入内容；不显示管理入口 |
| `me` 返回 `active`/`admin` | 进入内容；显示管理入口 |
| 开通成功后 | 当前会话直接进入内容，不需要重启小程序 |
| 收藏写入失败 | 提示失败，不显示"已收藏" |

## 云端验证（需已部署，无数据接口费用）

开通、管理和收藏都只读写已保存数据，不触发采集。验证时不要运行历史付费脚本。

1. **引导初始管理员**：用配置的身份打开一次，确认用户记录被建为 admin，管理入口出现。
2. **生成邀请码**：在管理页生成一个 `maxUses=1` 的码，记录码值。
3. **未开通账号**：用另一个真实微信账号打开，确认只看到开通引导，确认此时没有选题数据请求发出。
4. **开通**：输入码，确认立即进入内容；回到管理页确认用户列表出现该身份、`usedCount` 变为 1。
5. **码用尽**：用第三个账号提交同一个码，确认被拒。
6. **停用与恢复**：停用第二个账号，确认其刷新后看到停用提示；恢复后内容与收藏完整。
7. **收藏跨设备**：在一台设备收藏若干篇，清除小程序存储后重新进入，确认收藏仍在。
8. **最后一个 admin 保护**：尝试停用自己，确认被拒。

## 配额核实（spec FR-028，实施前置）

在腾讯云开发控制台回读并记录：

- 个人版套餐的云函数调用次数、数据库读／写次数、存储容量的配额与当前已用量。
- `EnableOverrun` 当前值（运行记录已载为 `true`，需复核）。

把数字写入运行记录，再对照 [research.md 7.4](research.md) 的估算判断 100 用户是否安全，以及是否需要采纳 7.5 第 3、4 项。**没有这组数字不得按 100 用户规模对外开通。**

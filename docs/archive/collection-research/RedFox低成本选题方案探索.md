# RedFox 小红书接口与低成本选题方案

核对日期：2026-09-09，北京时间。

后续状态：用户再次确认保持过去24小时、每日三个轮次、作者此前10条异常比较。本文仅保留为历史备选；当前方案与成本口径以[RedFox24小时异常监测抓取方案](./RedFox24小时异常监测抓取方案.md)为准。

这是方案探索稿。用户允许围绕接口能力重新比较产品规则；下文调整仍是建议，没有替换已确认需求。本轮只读取公开文档、接口目录和官方工具说明，没有注册、充值或调用业务数据接口。

**建议先验证 RedFox，再把首版收敛为“每日美食制作选题库”。** 用现成增长榜和关键词搜索找候选，把作者历史核验作为精选笔记的附加信息。这样能同时减少查询费用、登录维护和作者基准开发。

代价也明确：不能继续承诺每条都满足原来的五倍规则，也不能把昨日榜单当成过去24小时新发布的作品。更低的调用成本可以计算；内容质量和长期稳定性仍需实测。

## 1. 这次链接能做什么

用户提供的 [20060016](https://redfox.hk/apis/xiaohongshu/20060016) 是热门**账号**榜，适合发现对标作者。它支持日、周、月和“美味佳肴”分类，日榜在每天20:00更新昨天的数据。

它返回账号排名、粉丝和互动增量等信息，没有逐篇笔记内容。因此，首版核心应优先使用左侧的笔记搜索和笔记榜单。[官方接口元数据](https://redfox.hk/story/web/api/doc/detail/no/20060016)

### 榜单时间决定产品节奏

日榜官方核心说明把增长定义为：比较笔记发布后第三天与第二天的表现。该口径比页面概述更具体，应作为待实测确认的供应商定义，不能改叫自然日增长或作者五倍爆款。[日榜核心说明](https://github.com/redfox-data/redfox-community/blob/main/skills/xiaohongshu-dailytop/references/core_workflow.md)

日榜和七日榜都在每天19:00更新昨日榜单。官方默认规则是19:00之前取前天，之后取昨天。七日榜指向近期七天热门作品，但精确周期边界仍待核实。[七日榜核心说明](https://github.com/redfox-data/redfox-community/blob/main/skills/xiaohongshu-weeklytop/references/core_workflow.md)

例如9月9日20:00取到的，是9月8日榜单。页面应分别保存榜单日期、作品发布时间和本次查询时间；本次查询成功，不代表互动值刚刚刷新。

### “黑马”与“低粉”是两条接口

首页还有低粉爆款工具。官方说明是粉丝少于5000、点赞超过500，每天19:30更新昨日数据。它调用 `getXhsCozeSkillDataLowFans`，与黑马榜 `getLowPowderExplosiveArticle` 不同。[低粉接口说明](https://github.com/redfox-data/redfox-community/blob/main/skills/xiaohongshu-lowtop/references/api-spec.md)

这条低粉接口更贴近小账号借鉴需求，但当前目录未列出其对应价目，本轮也没有验证可用性。应作为待验候选；不能把它的阈值套给黑马榜，也不把未核实单价写入成本预算。

## 3. 推荐的产品调整

**保留“找到值得做的美食内容”这个目标，放宽昂贵的判断方式。** 建议方案如下，等待用户选择后才更新正式规则。

| 原方案 | 建议方案 | 取舍 |
| --- | --- | --- |
| 主要查过去24小时新发布 | 以近7天制作类选题为主，明确显示真实发布日期 | 能利用已有增长信号；会晚于作品首发 |
| 所有入选作品都查作者此前10条 | 榜单信号和内容价值先筛选，按需核验作者历史 | 大幅减少作者请求；未经核验的作品不标五倍 |
| 每天09、12、20点三轮独立采集 | 先每天20点生成一版，后续按实测刷新频率增加轮次 | 更贴近榜单更新；上午、中午沿用最新一期 |
| 强调是否为统计上的爆款 | 同时解释热度依据、制作价值和可借鉴角度 | 更贴近选题使用，但不承诺复制流量结果 |

候选发现流程：

1. 读取“美味佳肴”日榜与七日榜，获得供应商已计算的热门线索。
2. 用美食教程、家常菜、面食、烘焙、甜品、自制饮品、美食复刻、创意料理搜索补充；黑马和洞察接口用小样本比较增量价值。
3. 合并重复笔记，结合正文判断是否包含做法、配方或制作过程。纯探店、吃播、器具推广等不能仅因归入美食分类就入选。
4. 给有效笔记说明入选依据和可借鉴之处。图文与视频都保留；正文不足以判断时，标记待核实，必要时补详情。没有阅读视频内容时，不编造步骤或分镜。
5. 对值得进一步核验的笔记查作者历史。只有时间、此前10条和点赞依据都足够时，才显示作者相对表现；否则明确未核验或参照不足。
6. 合格结果自动进入往期库，保留原文链接、入选时数据和依据。同菜不同笔记可以分组，不能用分组悄悄丢弃合格结果。

不限定菜系、不要求维护对标名单、视频图文兼顾、跨日期去重、自动归档、合格结果不设数量配额，这些要求仍保留。

供应商TOP50是输入覆盖范围，不是我们的最终输出配额。搜索页数、失败、重复量和各来源覆盖也应记录；该方案不宣称搜遍全平台。

## 4. 成本怎么算

主要成本取决于查询次数。原方案大量候选来自不同作者，每个作者又需要历史查询，费用会随作者数增长。新方案先使用一批笔记自带的信息，作者核验不再是每篇入选的必要步骤。

下面是**每天一次、限定发现范围的费用算例**，不是正式采集上限，也不是保证产出数量。

| 每日操作 | 请求数 | 按标价计算 |
| --- | ---: | ---: |
| 8个关键词，各取最新、最热第一页 | 16 | ¥0.64 |
| 美食日榜、七日榜各一次 | 2 | ¥0.12 |
| 黑马榜覆盖8个关键词，分两组 | 2 | ¥0.08 |
| 候选发现合计 | 20 | **¥0.84/日，约¥25.20/30日** |
| 假设另补20篇详情 | +20 | +¥0.80/日 |
| 假设另核10位作者，每位一页足够 | +10 | +¥0.40/日 |

包含这两项假设补查时，合计为¥2.04/日，约¥61.20/30日。20篇和10位仅用于算账，不限制最终推荐条数；实际补查多少，就按实际请求计费。

这些金额只包括数据接口，不含AI分析、服务器、额外分页、重试或视频转录。多关键词是否按预期匹配、每页是否满额，以及不同来源重复率，都要实测；不能把20次请求说成获得固定数量的有效选题。

作为另一种规模说明：若搜索恰好用50页得到1000篇不同候选，数据发现费是¥2；如果再查1000位作者各一页，就增加¥40。保留全部作者核验时，换到低单价接口也无法消除这部分成本。这个例子与上表覆盖范围不同，不能当作同等效果的降价对比。

当前公开价格页写有最低充值100元；新账号工具说明也提到赠送积分，实际可用余额需账户确认。**预计消耗2元，不等于新账户只需充值2元。** 本次没有充值。[价格说明](https://redfox.hk/pricing)

## 5. 怎样让质量也提高

优质库是供应商的库名，不自动等于美食制作质量。我们要比较的是“拿到多少篇真正有用的选题”，以及每篇有用选题花了多少钱。

建议把高质量定义为：有可确认的制作内容；能说明值得借鉴的具体做法或角度；有可追溯的原文与热度依据；同质题材不会淹没其他菜系和形式。热度只是信号之一。

不要把低粉高互动、供应商增长排名、作者历史五倍混成一个指标。也不要把“5w+”等约数转换成精确值，再算带小数的增长率。洞察接口匹配不足时提供的其他热门笔记，必须重新检查相关性。[洞察元数据](https://redfox.hk/story/web/api/doc/detail/no/3X8FGEEM)

本轮发现公开示例存在字段类型和日期格式不一致，以及部分返回示例不是有效JSON。这说明接入前需要真实返回验收；不据此认定整个服务不可用，也不把文档当成稳定性证明。

## 6. 下一步的具体试验

先做一次最多32次请求、2元封顶的业务数据验证。计划正常调用30次，按当前标价共¥1.28，最多留2次额外校验；遇到权限、计费异常或预算到线即停止。

| 用途 | 请求数 | 估算费用 |
| --- | ---: | ---: |
| 8个关键词第一页，4个关键词第二页 | 12 | ¥0.48 |
| 黑马榜两组关键词 | 2 | ¥0.08 |
| 美食日榜与七日榜 | 2 | ¥0.12 |
| 两个具体主题的笔记洞察 | 2 | ¥0.12 |
| 8篇候选详情，检查文本与类型 | 8 | ¥0.32 |
| 4位作者列表，评估附加核验可行性 | 4 | ¥0.16 |
| 正常调用合计 | 30 | **¥1.28** |

先各取一个小样本，确认能返回有效数据，再在上述总量内展开。低粉专用接口的价目没有核实，不纳入自动尝试。

试验要回答：

- 哪个来源的制作类内容比例更高，能覆盖哪些菜系和图文/视频形式？
- 从结果中分来源抽查20篇，多少篇确实有可用做法或选题角度？
- 搜索与详情正文是否截断，补详情究竟增加了什么？
- 发布时间与榜单日期是否符合说明，返回的是多旧的数据？
- 不同词、页、来源有多少重复，细分搜索是否比单一分类榜多出有效内容？
- 实际扣费、空结果、失败和额外调用各是多少，每篇有效候选成本是多少？
- 作者列表能否与已有可靠样本对齐？若无法证明完整，就不提供严格五倍结论。

这次试验通过后，再连续观察7天、每天一版。首轮只能判断接口与内容是否值得继续；长期稳定性要单独记录成功率、数据更新延迟和人工干预次数。

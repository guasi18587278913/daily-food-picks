# 微信选题台跳转小红书笔记：路径调研

最新真机反馈：用户提供20:40手机截图，已进入标题为“小红书”的微信小程序，页面显示“安全限制／请在小红书APP上浏览该内容”。跨小程序入口已到达，但目标内容未展示，不能认定原文直达可用。仅凭截图不能判断是具体笔记、分享参数、账号状态或外部来源限制，也不能推广为所有笔记都会失败。

## 当前结论

找到此前未覆盖的重要候选：通过微信的`wx.navigateToMiniProgram`打开小红书在微信里运营的小程序，并传入笔记页面路径。已有第一手开发案例提供页面路径和官方主体截图；本地使用该AppID实际触发了微信“小红书”目标确认弹窗。**尚未验证手机能落到正确笔记，不能标记为已实现原文直达。**

此前测试只证明当前配置下普通HTTPS页面跳转失败、web-view因域名未配置失败，不能据此排除小程序间跳转。这个排查范围已纠正。

## 来源与证据等级

1. [微信官方接口](https://developers.weixin.qq.com/miniprogram/dev/api/navigate/wx.navigateToMiniProgram.html)：支持按appId/path打开其他小程序，也支持小程序shortLink。用户须主动点击，并确认微信弹窗。开发者工具不实际打开目标小程序，只支持接口校验。官方页面已通过直接HTTPS读取核对。
2. [开发者第一手案例，2024-09-14](https://www.phpriji.cn/blog/detail/find_miniapp_path.html)：展示如何从“小红书”微信小程序复制页面路径。截图主体为行吟信息科技（上海）有限公司，AppID为`wxb296433268a1c654`，原始ID为`gh_52be748ce5b7`；提供`pages/main/note/index`路径。它证明历史页面与参数线索，不等于2026年的端到端成功保证。
3. [供应商接口样本](https://s.apifox.cn/apidoc/docs-site/4012774/ru/316270753e0)：包含经`pages/main/home/index?redirect_path=...`跳到笔记的分享路径，是第二个待验参数候选，不是小红书承诺稳定的公开路由契约。
4. 本地保存的TikHub视频详情有`qq_mini_program_info`，其原始ID与上述微信小程序不同；没有把QQ字段冒充微信路径已验证。
5. [天天外链自身产品页](https://www.moreqifu.com/product/ttwl)：主要展示其他App进入微信、小程序的路径。该方向不能证明“微信小程序进入小红书笔记”可用；没有购买服务或把宣传当实测。

## 真机验收条件

1. 扫新预览码，点“直接打开这篇笔记”，确认目标为“小红书”后允许。
2. 必须看到上述指定笔记及相符标题/作者/视频；只打开首页不算成功。
3. 若直达停在首页，再测试“经首页打开这篇笔记”。记录是否要求登录、是否保留目标笔记。
4. 后续还需以另一条笔记和图文样本检查参数适用范围，再接入正式“查看原笔记”按钮并保留明确失败回退。

当前剩余：对照目标小程序的正常首页入口与官方分享入口，确认内容限制范围；可靠原文直达仍未验证，正式按钮未接入。下一步只采用正常产品入口核对，不猜造凭据或把安全提示当作加载成功。前述封面缺失问题独立待修，不由本次跳转调研替代。

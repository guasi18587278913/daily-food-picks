## 4. 不直接照抄的内容

| 教程中的说法或示例 | 本项目的处理与理由 |
| --- | --- |
| 30／150／800 行与作者自用的单文件 200 行限制 | 区分经验提醒和项目禁令。审查职责与可读性，不机械切文件；不接受新增千行手写业务函数 |
| 禁 npm、禁 require、统一某些库或框架 | 保留现有 npm、CommonJS 和原生小程序；工具取决于项目，不能把个人偏好当行业标准 |
| 名字里有 data／handle 就一定不好 | 判断具体范围是否清楚，公开协议字段和短局部变量允许合理例外 |
| 永不 catch、越短越好、禁止所有 TODO | 禁止隐藏错误、无用抽象和假完成；允许明确降级、必要说明和可追踪待办 |
| 所有 Skill 都要配 Hook 和子 Agent | 按任务风险和独立性选用。短流程无需为了课程作业要求增加机制 |
| Hook 100% 安全、子 Agent 自动保护隐私 | 还需核验事件覆盖、脚本结果、实际读写权限和数据处理；上下文隔离不是权限隔离 |
| 每改一个文件就跑全量测试 | 采用用户已规定的分阶段验证；开发中只跑受影响范围 |
| 测试与实现分两个 AI 就能保证正确 | 独立审查有助于发现盲点，但需求、测试和实现仍需核对证据 |
| 跑三遍之后即可无人值守 | 看对应风险与验收结果，包括失败、重复、恢复和停止，不把固定次数当可靠性保证 |
| 课程实验失败也算完成 | 学习成果与已承诺的产品验收分开记录 |
| Codex Skill 是 TOML，必须手工注册 | 正文是 `SKILL.md`，支持目录发现；TOML 管理工具配置。见下面官方依据 |
| 超过 500 行会被各工具统一静默截断 | 不采用这一固定断言。当前 Codex 官方区分初始技能列表预算与选中后的完整正文读取 |
| 工具价格、模型榜单、增长比例和平台技巧 | 都不写成长期工程规则。真实任务需要时再核验，不为读完教程安装整套工具或扩张业务 |

本规范继承用户的风险分级、授权持续有效、针对性验证和高风险独立审查要求。教程建议与这些要求冲突时，以当前项目约定为准。

## 5. 官方核验

[OpenAI Build skills](https://developers.openai.com/codex/build-skills)确认：技能目录以 `SKILL.md` 为核心，包含名称与用途说明；可带脚本、参考和资源。Codex 先识别元信息，选中后读完整正文；项目级技能可从 `.agents/skills/` 发现。

[OpenAI Save workflows as skills](https://learn.chatgpt.com/use-cases/reusable-codex-skills)强调：从成功工作样例开始，提供真实说明、命令和好结果，再创建、验证，并根据使用反馈修订。

核验日期为 2026-09-13。后续配置具体 Hook、权限和其他 AI 工具时，应再核对所用版本的官方接口，不直接运行课程截图中的配置。
